# P4 · 小程序进度回写契约

> 版本：v1.0（四期） · 关联：`docs/architecture.md` §5.2 W1 / 验收 D7
> 面向：微信小程序开发方（订单前端 / 发货端）与虹越平台联调

## 1. 背景

小程序是已有系统（订单前端 / 发货端），虹越平台负责生产执行（排产 / 报工 / 入库）。
四期提供 **进度回写契约 API**：小程序可按「订单 / 产品」维度查询实时生产进度
（完成数量、进度%、预计完成时间、延期标识、可发货量 = Σ已入库），
并提交发货状态（占位，完整发货收口在五期）。

## 2. 鉴权（appKey + HMAC-SHA256）

所有 `/api/mp/*` 接口使用 **请求头签名**，与用户 Token 无关。

| Header | 说明 |
|---|---|
| `X-App-Key` | 应用标识（测试密钥见 §6） |
| `X-Timestamp` | Unix 秒级时间戳，偏差 ≤ 300s（防重放） |
| `X-Signature` | 签名串，见下 |

签名算法：

```text
canonical = "{timestamp}\n{METHOD}\n{path}"
X-Signature = base64( HMAC-SHA256( app_secret, canonical ) )
```

- `METHOD`：大写，如 `GET`
- `path`：`$request->path()`，即 **含 /api 前缀、无前导斜杠** 的完整路径，如 `api/mp/orders/SO20260101-001/progress`
- 示例（伪代码）：

```js
const crypto = require('crypto')
const ts = Math.floor(Date.now() / 1000)
const canonical = `${ts}\nGET\napi/mp/orders/SO20260101-001/progress`
const sig = crypto.createHmac('sha256', APP_SECRET).update(canonical).digest('base64')
// Headers: X-App-Key, X-Timestamp: ts, X-Signature: sig
```

## 3. 接口清单

### 3.1 订单级进度

```http
GET /api/mp/orders/{orderNo}/progress
```

`orderNo` 支持：平台订单号（`SO...`）或金蝶生产订单号（`k3_bill_no`）。

响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| level | string | `order` |
| biz_no / order_no | string | 订单号 |
| order_id | int | 订单 ID |
| qty | int | 订单总量（Σ明细数量） |
| done_qty | int | 完成量（Σ任务完成） |
| progress_pct | int | 进度 % |
| expected_finish | string\|null | 预计完成（任务计划结束最大值） |
| delayed | bool | 是否延期（交期已过且未完工） |
| shipable_qty | int | 可发货量（= Σ已入库 stocked_qty） |
| status | string | pending / in_progress / done |
| updated_at | string | 数据时间 |

### 3.2 产品级进度

```http
GET /api/mp/products/{productCode}/progress
```

跨订单按产品编码聚合，字段同上（`level=product`，`product_id/product_code`）。

### 3.3 通用查询

```http
GET /api/mp/progress?order_no={orderNo}
GET /api/mp/progress?product_code={productCode}
```

二选一；都为空返回 422。

### 3.4 发货状态提交（占位）

小程序提交发货单（选单 / 分批 / 拍照 / 物流）：

```http
POST /api/shipments
Authorization: Bearer <平台用户 Token>
Content-Type: application/json
```

请求体：

```json
{
  "order_id": 3,
  "receiver": "李经理",
  "address": "合肥市包河区...",
  "logistics_no": "SF1234567890",
  "photo_url": ["https://oss.../ship-1.jpg"],
  "lines": [
    { "product_id": 1, "qty": 300 }
  ]
}
```

响应 `data`：`{ shipment_no, status: "pending", lines }`；随后可调：

```http
POST /api/shipments/{id}/stock-check   # 发货前金蝶库存校验（四期占位）
PATCH /api/shipments/{id}/status       # { status: pending|partial|done, logistics_no? }
```

## 4. 平台 → 小程序 推送（W1 反向）

平台在报工 / 排产 / 入库事件后及定时兜底（每 30 分钟）推送进度到小程序端点
（`config('mp.push_url')`，由小程序开发方提供）。未配置时仅写 `integration_logs`（api_type=push_progress），
不影响平台业务。推送同样使用 §2 签名。

## 5. 幂等与重试

- 查询类：无副作用，可直接重试。
- 发货提交：`shipment_no` 唯一；重复提交请先按 `shipment_no` 查重。
- 进度推送：`integration_logs` 记录 `api_type=push_progress` + 成功唯一键；断网重试由平台队列兜底。

## 6. 测试密钥与联调信息

| 项 | 值（默认，`config/mp.php`，可用 env 覆盖） |
|---|---|
| X-App-Key | `hy-mp-demo-key` |
| app_secret | `hy-mp-demo-secret` |
| 时间戳偏差 | 300s |
| 基础地址 | 由部署环境提供（联调环境由客户分配） |

自测示例（bash + openssl）：

```bash
TS=$(date +%s)
PATH_STR="api/mp/orders/SO-TEST/progress"
SIG=$(printf "%s\nGET\n%s" "$TS" "$PATH_STR" | openssl dgst -sha256 -hmac "hy-mp-demo-secret" -binary | base64)
curl -s "https://<host>/api/mp/orders/SO-TEST/progress" \
  -H "X-App-Key: hy-mp-demo-key" \
  -H "X-Timestamp: $TS" \
  -H "X-Signature: $SIG"
```

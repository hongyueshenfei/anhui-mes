二、各类数据生成逻辑

1. 订单（12 单，覆盖全状态）

状态订单数代表客户/产品业务含义
pending2日用品商超（P-0003）、家居百货（P-0004）已录单未排产 → 红灯“未排产”，刻意不建排程
scheduled2连锁餐饮（P-0001）、老字号食品（P-0002）已排产未开工（排程时间已排定）
in_progress5美妆电商、快消品、洗护、外贸（双行）、餐具厂在产：排程 + 前两工序已报工（50% 进度）
produced3饮料灌装、碳酸饮料、美妆品牌二已完成：全工序报工满额 → 任务 done → 订单完结

2. 任务（13 个）

由 OrderService::createOrder 自动创建：每订单行 1 任务，绑定产品的默认工艺（route_id）与默认模具（mold_id），初始状态 unscheduled。

3. 排程（44 段 = 11 任务 × 4 工序）

  • 入口：ManualScheduleService::save → 引擎 buildChain 按工艺路线自动拆 4 段全链（成型机台 + 喷漆/效果产线 P-01 + 包装产线 P-02），各段 qty = 任务量、时间依产能/班制推算
  • 成型机台取自模具适用清单首台（如 M-005 → I-03）；三匹配（产品-模具-机台）由引擎强校验
  • 时间网格：全部排程起点按 5 天步长错开（产线链最长约 4.3 天），同机台/同产线零冲突（实测通过）
  • 排程后任务置 scheduled；订单状态由 syncStatus 按任务状态聚合派生

4. 报工（24 条，车间强匹配）

场景逻辑
已完成（produced）任务累计报工 = 任务量 × 100%，按工序段均分（余数归末段）；完成后任务 done
生产中（in_progress）前两段合计 50%（成型 35%、第二段 15%），任务保持 in_progress
报工人按资源车间匹配：成型段注塑车间（W001）/吹塑车间（W005 补充工人）、喷漆效果段（W003）、包装段（W004）
口径任务完成 = 跨段累计报工达任务量（服务端 assertWithinAllowance 防超报）

5. 模具使用量（与订单/报工严格对账）

通过报工事件链自动联动，非手工写入：报工 → ReportSaved 事件 → UpdateMoldLife → opened_count += 合格数 ÷ 模穴数（ceil）+ 写入寿命日志（含 task/report 引用）。

三、实体关联关系

Order 订单 → OrderLine 订单行(mold_id) → ProdTask 任务(route_id, mold_id) → TaskSchedule 工序排程(机台/产线) → WorkReport 报工(schedule_id, worker)

模具侧：Mold.opened_count = Σ MoldLifeLog.opening_count = Σ(报工合格数 ÷ 模穴数)；每条寿命日志可追溯到 task/report → 订单。

状态联动：任务状态（unscheduled → scheduled → in_progress → done）→ syncStatus 聚合出订单状态；报工自动刷新任务进度与模具寿命。
